# 交付产物规范与排版标准 (Delivery Matrix & Standards)

本文档定义系统输出的三类核心交付物标准、结构规范与排版格式。

---

## 产物体系总览

| 维度 | 产物 A：单集教材长文 | 产物 B：模块复习笔记 | 产物 C：模块合辑教材 |
| :--- | :--- | :--- | :--- |
| **文件位置** | `output/<task>/articles/PXX_*_精读文章.md` | `output/<task>/notes/模块xx_xxx_笔记.md` | `output/<task>/textbooks/模块xx_xxx_精读全书.md` |
| **适用场景** | 单集定向查阅、微粒度推导理解、自学跟学 | 考前复习、日常速查、XMind/Markmap 脑图导入 | 体系化通读、跨章节演进串联、完整教材阅读 |
| **内容范围** | 单分集完整覆盖，原汁原味还原推导过程 | 跨分集核心知识点归纳与横向对比 | 模块内所有分集长文的章节化整编 |
| **文风语感** | `learning`（推荐）：保住讲师的讲课口吻（我/我们/你们、设问反问、比喻、轶事、临场判断），写成通顺的书面讲解而非教材式客观陈述；`legacy`：客观学术第一视角、去口语化。两者都要求高信息密度、无注水段落 | 条目化、树状节点展开，高信息密度 | 体系化章节体，包含导读、章节过渡与模块总结 |
| **代码/公式** | 完整保真，包含推导演算与逐段解析（只写语料真实讲到的） | 签名、关键片段或语法要点速查 | 生产级代码示例、架构图完整保留 |
| **思考自测** | `learning`：**仅当讲师课上确实提到题目时**，才在文末还原《本讲提到的题目》；他没提就绝不自行命题。`legacy`：按内容自适应附 2~3 道随堂自测（宏观通识类自然收尾） | 以速查条目为主，不包含大题 | 模块综合练习题与技术总结 |

---

## 产物 A：单集教材长文 (`articles/`)

每个视频分集独立生成一篇教材长文，目标是让读者无需观看原视频即可获得完整技术细节。

### 0. 长文类型判定与提示词类型矩阵（工作流第一步）

不同形态的长视频讲法完全不同：系统网课是“成体系地讲一门知识”，咨询答疑是“提问—解答”，访谈是“多人交替说”。用同一份写作提示词去套，必然写出不像讲义的产物。因此主 Agent 必须在跑 `pipeline` / `transcribe` 之前，先读**课程标题与分集标题**判定类型，并显式传 `--article-type`：

| 类型键 | 中文名 | 判定信号 | 提示词状态 |
| :--- | :--- | :--- | :--- |
| `learning` | 学习类（系统网课 / 公开课 / 讲座） | 标题含「第 N 讲 / 第 N 章 / 绪论 / 概述 / 原理 / 基础 / 入门 / 进阶 / 复习 / 习题课」；分集连续编号、每集围绕一个知识主题系统讲授 | **已提供（推荐，当前版）** |
| `legacy` | 旧版（改写前的原稳定版） | 用户明确要求沿用旧写法（「还用以前那版」「按稳定版来」），或不需要讲师讲课口吻、只要客观教材式长文 | **已提供**（教材腔、客观学术第一视角、随堂自测） |
| `consulting` | 咨询答疑类（择校规划 / 答疑 / Q&A） | 标题含「咨询 / 答疑 / 问答 / Q&A / 怎么选 / 怎么办 / 经验分享」；以提问—解答推进 | 已登记，提示词未提供 |
| `interview` | 访谈对谈类（嘉宾访谈 / 圆桌 / 连麦） | 标题含「访谈 / 对话 / 对谈 / 圆桌 / 连麦 / 聊聊」；多人交替发言 | 已登记，提示词未提供 |
| `review` | 测评体验类（产品测评 / 上手 / 开箱） | 标题含「测评 / 评测 / 体验 / 上手 / 开箱 / 实测对比」 | 已登记，提示词未提供 |
| `livestream` | 直播闲聊类（直播回放 / 闲聊杂谈） | 标题含「直播 / 回放 / 闲聊 / 杂谈 / 唠嗑」；无固定教学结构 | 已登记，提示词未提供 |

**已提供提示词的只有 `learning` 与 `legacy` 两种**（推荐 `learning`）；其余四种形态只登记、不提供提示词。
**未命中即终止**：未指定类型、拼写无法命中、或判为「提示词未提供」的类型时，命令打印类型菜单并 `exit 4`，**不落盘任何任务书**；既不要换个类型名重试，也不要手工套用别的提示词继续写。命中的类型会写入任务书抬头与 `manifest.json` 的 `article_type` 字段。

### 1. 学习类长文写作取向（`learning`，默认推荐）

- **保住讲师的讲课风格**：用“我/我们/你们”讲，保留设问与反问、强调与反复告诫、临场判断、自造比喻、真实轶事（人物/时间/数字/结局）、自嘲与调侃，以及他解释“为什么这么定”“当年踩过什么坑”的段落。轻松感来自这些由头、例子与讲法，**不来自注水**。
- **高信息密度**：语料中真实存在的推导链条、运行机理、算法步骤、公式证明、边界条件与参数细节完整保留；“讲透”不等于“铺开”——同一件事只讲一次，读者一遍就懂的地方不铺垫，每一段都必须有信息增量，凑不出信息的段落直接删掉。
- **成稿观感**：**标题用技术文档的朴素写法**——编号加术语或名词短语（`## 1.` / `### 1.1`，如「2.1 执行单元 EU 的控制部件」），只负责检索与定位；**严禁口语化、修辞化、带语气或带悬念的标题**（比喻、设问、调侃留在正文）。**标题的数量与切分跟着这一讲走**：按讲师自己的分块分节（他一个问题讲完再讲下一个），不要另起一套分类框架；**不许硬造子标题**（没有并列关系的内容不凑 `###`；某标题下只讲得了一两句话就并回去）；**标题不构成"这一节要写满"的义务**——他一句话带过的地方正文就一句话带过，不补描写、不补例子、不补推导。层级只用三层且**全篇一致**；**不许空壳层级**（`##` 下只有一个 `###` 就抬平，拆 `###` 至少两个）；同层编号连续、同属一类；不写「其他/补充/小结」这类空标题。关键定义/结论用 `> **定义**：`、`> **结论**：` 单独成行；确有对比才用 GFM 表格；字符画必须进 ` ```text ` 围栏；篇幅由内容决定。
- **该清与该留**：清掉设备调试、点名考勤、课间串场、平台互动、纯填充口头语、括号里的舞台提示（如“（笑）”“（停顿）”）、重复结巴与残句；留下比喻、轶事、设问、告诫与临场判断。

### 2. 去模板化与因材施教规范 (Anti-Formulaic Guidelines)

> [!WARNING]
> **【严禁模板八股】**：
> 严禁所有分集机械克隆相同的二级标题（例如全部强套 `## 1. 为什么需要它：现实痛点与历史由来` 属于严重缺陷）。
> 必须根据分集的实际学科属性与讲师原课讲授脉络，灵活拟定章节标题与开篇逻辑：

- **类型 1：理论概念型（如数据模型、概念抽象、三级模式）**
  - **开篇逻辑**：直击核心概念的形式化定义与现实对象映射，紧扣原视频中讲师使用的生动教学比喻（如数字“93”与语义的结合、学生档案照片体现多模态数据、仓库与仓库管理员类比 DBMS）；
  - **结构示范**：`## 1. 核心概念与本质内涵` -> `## 2. 体系结构与映射机制` -> `## 3. 典型例题与认知辨析`。
- **类型 2：语法实操型（如 SQL 基础、DDL 建表、ALTER 修改、视图消解）**
  - **开篇逻辑**：开门见山展示标准语法骨架，并结合经典教学数据模型（如经典的“学生-课程-选课”表）直奔语句语义；
  - **结构示范**：`## 1. 语法体系与基本规约` -> `## 2. 典型业务操作与代码演练` -> `## 3. 执行边界与避坑要点`。
- **类型 3：算法演算与证明型（如关系代数、范式判定、模式分解、查询优化树）**
  - **开篇逻辑**：直接提出问题形式化规约与算法目标，展开严密的数学演算步骤与中间关系变换过程；
  - **结构示范**：`## 1. 算法形式化规约与理论目标` -> `## 2. 逐步推导与中间关系演算` -> `## 3. 经典考题与证明实战`。
- **类型 4：系统机理型（如 WAL 日志、检查点恢复、三级封锁协议、两段锁 2PL）**
  - **开篇逻辑**：直接阐明底层系统设计的核心矛盾（如性能与一致性冲突、并发三大不一致性成因），解构其内部调度逻辑；
  - **结构示范**：`## 1. 核心矛盾与机理剖析` -> `## 2. 协议规则与状态流转` -> `## 3. 异常场景诊断与恢复策略`。

### 3. 事实准确与去噪 (Grounding & Style)
- **课堂事实锚定**：正文必须包含原视频中讲师亲口讲述的具体数值、例题题干与板书比喻（Grounding Evidence）；
- **静默校正口误**：讲师课上的偶发口误（如引脚电平说反、位权说反）直接在正文中静默修正，绝不撰写“原声挑错”段落；
- **没说的不编**：讲师只在幻灯片上展示、音频里没有逐字念出的代码或表格，**不要替他补写**，更不要基于补写出来的内容做逐行解析；
- **高校学术语境**：以经典教材（如王珊/萨师煊《数据库系统概论》）与 408 考研大纲为准绳，严禁脱离课程生搬硬套互联网大厂微服务、分布式等浮夸黑话。

### 4. 单集保留纪律
在执行阶段二模块整编时，`articles/` 目录下的所有单集文章**严格保留，不得删除**，供用户定向精读与按讲溯源。

## 产物 B：模块复习笔记 (`notes/`)

模块笔记聚合跨分集的核心概念，以结构化、高密度的形式呈现。**笔记只有这一种风格**（旧版八种风格矩阵已删除），无需 `--style`：

> **语料纪律（v1.7 起）**：模块笔记的唯一事实来源是**该模块各集单集精读长文**（`articles/`），
> 撰写前必须逐篇整篇读完（任务书中列出路径清单与字节数）。知识元（kernel）已降级为可选索引，
> 默认不参与——空壳知识元会把笔记质量一并拖垮。

### 0. 笔记规范（构件 + 禁令 + 密度纪律）

| 必备构件 | 要求 |
| :--- | :--- |
| H1 标题 | 用模块主题命名（不得是分集编号或分集标题） |
| 元信息抬头 | 紧随 H1 的 **2 行**引用块：`> 整理自《课程全称》Pxx~Pyy 单集精读长文` + `> 渲染支持：Typora / VS Code Markmap / XMind 一键脑图` |
| 知识拓扑树 | 一棵 ` ```text ` 围栏树，一级节点标分集区间，末级 `────` 引线横向对齐同一列（宽度按「汉字 2 列、ASCII 1 列」算） |
| 主题分节 | `## 1. <主题>` … 每节首行 `> **一句话主旨**：…`（30~60 字） |
| 概念块 | `* **术语（English，缩写）**` → `* > 定义：…` → 条件/数值/规则/边界条目 → `* > 易错点：…`（确有才写） |
| 溯源标注 | 每个概念块末尾 `* > 来源: P03, P05` |
| **不收尾** | 写到最后一个知识主题就结束：**不写「速查卡」，也不写「一句话总纲」**（与树、条目重复，已废弃） |

| 禁令 | 典型反例 |
| :--- | :--- |
| 禁分集平铺标题 | `### P01 第1章 绪 论（1）`、`### 1.1 第16讲 SQL 概述` |
| 禁分集口吻 | 「本集中」「上一讲」「视频里提到」 |
| 禁套话填充 | 「概念属性与边界」「形式化表述与理论依据明确」「符合全国计算机专业考纲核心知识点」 |
| 禁中途截断 | 「……由不同的程序员自」（句子被砍断）、行内塞入 `> **易错点**` 导致渲染破损 |
| 禁硬造子标题 | 没有并列关系的内容硬凑 `###`；某标题下只讲得了一两句话却不并回上一节 |

> **密度纪律（第一条）**：**只写结论，不写推导**——每条写清"是什么、条件是什么、数值是多少、规则怎么定、边界在哪里"就够了；
> 不写"为什么"、不写推理过程、不写讲解铺垫、不写举例说明，机理也压成一句话结论。
> 实测（第 6~8 轮，同一位讲师同一讲）：这一条把笔记体量从长文的 105% 压到 62%。

> **两条排版硬约束**：① 概念块里的 ` ```text ` 字符画**围栏整体缩进 4 空格**留在列表项内（写在第 0 列会终止列表、渲染时概念块断成两截）；
> ② 拓扑树末级注释**纵向对齐同一列**，宽度按「汉字 2 列、ASCII 1 列」计算。

以上禁令由 `python scripts/note_quality_check.py --strict` 机器验收（在两套人工精修语料上实测 0 命中）：
其中「套话填充 / 空壳标题 / 分集平铺标题 / 行内残缺引用 / 分集口吻」为**致命项**（必须清零），
「断句（默认每份 ≤ 4 处）/ 结构缺件」为**提示项**——结构缺件需加 `--require-structure` 才纳入门禁。

### 1. 概念块写法（唯一风格）
严格对齐技术脑图的可扫读规范，天然支持 VS Code Markmap 或 XMind 导入：
- 采用标准 Markdown 标题结合多级无序列表（`*`）层级缩进；**标题只到 `##` 主题层**，概念一律用列表层级展开；
- **核心定义**采用单行引用：`    * > 定义：…`；
- **条件 / 数值 / 规则 / 边界**一律条目化，一条一件事，只写结论不写推导；
- **易错点**必须是独立缩进的引用行（`    * > 易错点：…`），严禁写在列表项正文中间；
- 避免冗长散文段落，保持高信息密度与快速扫读体验。

### 2. 核心知识拓扑树规范 (ASCII Topology Tree)
在模块笔记开头提供简洁明了的 ASCII 拓扑树，展示核心知识骨架；
**末级注释必须纵向对齐到同一列**——算宽度时一个汉字按 2 列、一个 ASCII 字符按 1 列：
```text
模块：数据库系统概论
├── [1] 绪论与数据模型
│   ├── 核心概念 ────────── 数据、数据库、DBMS、DBS
│   └── 体系结构 ────────── 三级模式与二级映像
├── [2] 关系模型与关系代数
│   ├── 完整性约束 ──────── 实体、参照与用户定义完整性
│   └── 专门关系运算 ────── 选择、投影、连接、除运算
└── [3] 关系数据理论
    ├── 函数依赖 ────────── 完全/部分/传递函数依赖
    └── 范式规范化 ──────── 1NF -> 2NF -> 3NF -> BCNF
```

## 产物 C：模块合辑教材 (`textbooks/`)

在模块内所有单集长文生成完毕后，按章节整合为连贯的模块教材：
1. **章节编排**：消除单篇间的孤立感，统一组织为 `导读与目录 -> 子章节 -> 模块技术总结`。
2. **逻辑过渡**：在各小节切换处补充承上启下的承接段落，梳理知识点演进脉络。
3. **安全整编**：整编仅向 `textbooks/` 写入新文件，原 `articles/` 目录完整保留。

## 排版与格式要求

1. **书面讲解文风**：压掉口语的啰嗦、语气助词与填充词（如“老铁们”、“咱们来看一下”），写成通顺的书面讲解；但**不得改写成教材式的客观陈述**——讲师的讲课口吻、比喻与轶事要留住（单集长文见上文「学习类长文写作取向」）。
2. **代码块**：必须显式标注语言标识符（如 ````sql`, ````python`, ````bash`, ````c`）。
3. **公式规范**：数学与逻辑公式统一采用 LaTeX 语法包裹（行内 `$O(n \log n)$`，行间 `$$...$$`），避免转义符号污染。
4. **表格规范**：表头对齐，对比维度清晰明确，单单元格避免超过 100 字符；确无对比要素时不画表。
5. **事实保真**：以原音视频实际讲解内容为唯一事实依据，原内容未涉及的部分明确标明“未说明”，严禁主观臆造外部结论；讲师只在幻灯片上展示而未念出的代码或表格不得替他补写。
6. **标题与可扫读**：单集长文 `#` 只作篇名、脉络用 `##`、细分用 `###`；关键定义与结论用 `> **定义**：`、`> **结论**：` 单独成行，便于扫读与检索。

## 渲染兼容规范（阅读器以 Typora 为准）

三类交付物的默认阅读场景是 **Typora**，同时需兼顾 VS Code Markmap、XMind 导入与纯文本查看。因此产出必须遵守以下硬性写法：

### 1. 结构图必须进围栏（最高优先级）

- 凡用字符拼出的**拓扑图、框图、系统结构图、时序示意、对齐示意图**，一律**必须**置于 ` ```text ` 代码围栏内；
- **严禁**把字符画裸写在正文里：Markdown 渲染器会合并连续空格，导致图形彻底错位，变成一段无法阅读的符号流；
- **围栏必须成对闭合（有开必有闭）**，严禁留下孤立的 ` ``` ` 行——否则文末会渲染出一个空代码块；
- 围栏内不得混用行内标记（如加粗、行内代码），以免破坏字符对齐。

### 2. 提示与注意事项：禁用 GitHub 专有告警块

- 统一写法：`> **提示**：……`、`> **注意**：……`、`> **易错点**：……`、`> **定义**：……`；
- **严禁**使用 `> [!TIP]`、`> [!NOTE]`、`> [!WARNING]`、`> [!IMPORTANT]` 等 GitHub 专有告警语法——旧版 Typora 不识别该语法，会把 `[!TIP]` 字样原样显示出来。

### 3. 公式的阅读侧设置

- 公式语法见上文「排版与格式要求」第 3 条（行内 `$…$`，行间 `$$…$$`）；
- **阅读侧需一次性设置**：Typora → 偏好设置 → Markdown → 勾选「内联公式」（Inline Math）。未开启时行内公式会原样显示 `$…$` 源码，看起来像公式损坏。

### 4. 其余写法约定

- **代码块**必须标注语言标识符；字符画一律用 `text`，不得留空语言；
  > **门禁口径**：`render_compat_check.py --strict` 的致命项只有「GitHub 告警块 / 围栏外裸字符画 / 围栏配对」三项；
  > **缺语言标识默认只统计不拦**（历史成品存在既有缺口），要死守时加 `--require-lang`；
- **音频码率备注**（非排版项，供排查体积问题）：B 站链路下载后统一转封装为 **16kHz 单声道 32kbps AAC**（`fetcher.py`），
  本地媒体提取为 **16kHz 单声道 64kbps AAC**（`local_media.py`）；文档一律只承诺「16kHz 单声道」；
- **表格**使用标准 GFM 表格，表头必须带对齐行（`| :--- |`）；
- **标题层级不得跳级**（例如 H2 直接跳到 H4），以保证 Typora 大纲面板与导出结构正确；
- `---` 分隔线**前后必须留空行**，否则可能被解析成上一行的“标题下划线”，把整段正文变成标题；
- **不使用裸 HTML 标签**，**不使用 mermaid**：二者会破坏 XMind / Markmap 导入与纯文本可读性；
- emoji 与任务清单复选框 `- [ ]` 可正常使用（Typora 原生渲染）。
